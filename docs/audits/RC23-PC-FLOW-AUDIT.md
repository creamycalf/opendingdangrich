# RC23 后台与资源加载修复（2026-11-10）

本轮在RC22基础上修复呈现层可靠性，没有修改原版规则实现。RC22仍存在的差异继续有效，见RC22-PC-FLOW-AUDIT.md。

- 月结、GAME OVER、胜利片头/片尾、证书和原标题统一先等待图片load再decode。使用有界并发，错误/超时终止同批请求；退出可取消进行中的加载及解码，不再等待旧资源插入新页面。
- 证书入口在main.ts接入场景取消信号；离开后迟到失败不会重新打开成绩页，证书音乐保持原胜利曲。
- 仙人组件自身的后台时钟冻结，隐藏时不推进动画或发声。实际游戏原先会在切后台时打开暂停菜单并销毁仙人组件，此路径保留，恢复时重新进入，不把组件风险称为已经证实的生产跳帧。
- 棋盘状态结束反馈在隐藏时立即取消，避免返回后补播旧音效。游戏规则和已结算奖励不因演出重新执行。

同一名称曾同时存在image-loader.ts与旧image-loader.mjs，Vite会解析到旧模块；构建检查发现后将新增模块命名为scene-image-loader.ts，旧棋盘加载器保留。

验证范围以交付verification.json中的浏览器与最终APK报告为准；所有原生测试先备份，再恢复GameSave及全部localStorage并重载核验。未清除用户数据。规则回归引用RC22的349项基线，不冒称此次重跑。

## 实际验收中的等待时间

最终APK模拟器出现首次/重新进入时加载偏慢：真人胜利首轮约10.6秒；仙人好箱首图约12.8秒、首句约15.8秒（包括原入场动画），续档图像约12.5秒。图像请求与解码完成后流程正常，测试按加载和演出分别限时，没有将超时失败冒充成功。并发限制、模拟器/磁盘状态都会影响结果，目前不将本轮称为性能优化；此项仍待继续改善。不同机器与实体手机的具体时间未知。停止资源校验后单独复测真人仍约9.35秒：实际199张图的decode累计约17.94秒，4并发分批是明确成本，不仅是磁盘竞争。后续可对胜利场景单独提高并发并在最终APK验证；本轮未把该优化冒充已完成。
