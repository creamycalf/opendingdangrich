# 引擎重写与触屏移植路线

用户提出参考 Red Alert 2 的策略。暂按此前浏览的 https://github.com/rust-alert/ra2.exe 理解；若用户指另一项目，以实际项目为准。

2026-11-02 核对该项目 README：它读取玩家提供的游戏数据，以自有引擎推进对局，渲染消费状态快照；不是把 Windows EXE 自动转换为手机程序。文档标注 Web/Wasm 部分仍为占位，不能视为已完成的安卓移植方案。

## 采用的原则

1. 保留叮当原版资源及可验证玩法，使用独立游戏引擎，不以 Windows EXE 兼容层作为最终手机运行前提。
2. 引擎处理掷骰、移动、经济、事件、道具、角色和小游戏状态；不依赖 DOM、触屏、Canvas 或 Android API。
3. 触屏层提交语义命令，例如掷骰、选择方向、选择地产、确认交易、使用道具。渲染和动画读取状态，不另行计算规则。
4. 存档保存权威游戏状态与随机数状态；加载、断点续玩和回放走相同命令路径。
5. 以本地原 EXE 反汇编/CPU 仿真/原版实机观察为规则依据。测试自身实现只能证明一致性，不能把猜测规则变成原作证据。

## 沿用与替换

沿用现有资源解析、八图数据、原机器码验证导航、触屏手势、Android 打包工程。暂时保留 TypeScript 实现；更换 Rust 不会自动补全未知规则，无充分理由不为换语言重做已有工作。

当前已用原静态证据和机器码对照替换核心经济、事件与42种道具实现，八款小游戏和音频均已接入。完整内容测试候选为1.0.0-rc1；详细结果见FULL-GAME-ACCEPTANCE.md和ANDROID-VALIDATION.md。电脑策略、随机数和手机镜头采用移植版实现，不宣称逐指令相同。

最终安装包仍须独立核对资源完整性、安卓触屏、暂停和冷启动恢复；源码数量或规则自测不能替代这些运行检查。
