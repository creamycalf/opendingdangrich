# 时光机与六槽滚动历史

规则28纠正一项错误判断：Database文件不是缺失的安装素材，而是原版游戏运行中自动生成的历史存档。不能仅因解压目录里没有该文件而永久禁用仙人事件33。

## 原版证据

目标wa.exe SHA256 `f190b35370d3efe3024b5105a90f85abf07f5915e7b7a431d93b756de03f65f3`，Ghidra12.1.4静态反编译。完整证据在research/historyXrefs28.json、history28.json、historySave28.json；snapshot为ghidra-rules28-history.snapshot.json。

- `0x4739c0`：首次开始玩家循环，以及再次回到首个存活玩家时，调用`0x48a2e1(next+10)`，随后next递增，大于5回到0。循环存档发生在减速日期推进分支之外，因此记录玩家循环，不单按日历天数计。
- `0x48a2e1`：参数大于等于10时写Database%04x.dat；记录日期、当前玩家、全局经济、人物、地图、建筑等。没有保存随机数发生器状态。
- `0x41373a`：检查next槽位是否存在；六槽首次填满后，next所指即最早的一份。`0x4136f3`设置加载标志及该槽位。
- `0x473813`转入`0x48aa52`加载；加载函数删除六份历史文件、next归零，再恢复全局、角色和地图。
- `0x455468`及`0x476651`在启动/新局清空历史或重置计数。

## 移植实现

新局记录第一份快照；每次完整玩家循环开始时覆盖一槽，最多六份，不把历史嵌套进历史。填满前事件33不参与抽取。触发后恢复最早槽位，保留当前随机流并清空六槽，避免用旧随机种子重复触发相同事件。

回溯后展示确认消息，继续时返回被恢复玩家的掷骰前阶段。资金、土地、建筑、库存、状态、位置、全局经济、日期等均恢复。事务序号保持递增，方便手机事件循环识别新的状态。

手机自动存档会同时保存六份历史，以支持应用被系统关闭后无损续玩；这是相对原版显式读档会清空历史的适配差异。旧版触屏存档迁移时历史为空，从后续循环开始积累，不伪造过去。
