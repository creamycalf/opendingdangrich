# 本地原程序导航逻辑恢复

源文件：工作副本 `wa.exe`，SHA-256 `f190b35370d3efe3024b5105a90f85abf07f5915e7b7a431d93b756de03f65f3`。

本机版本的方向构造函数为 **0x47db4d**，正常导航查询为 **0x47ab39**。不能套用另一版本研究笔记中的绝对地址。

## 已确认的分支

- 坐标方向依次为北、南、西、东，输出位依次为 1、2、4、8。
- 前方邻格可通行时保留前方。
- 左右邻格均通行时，分别检查左右第二格；只有第二格通行才加入相应转弯方向。
- 左右及前方都不通行时，函数仍检查正前方第二格。这是原函数的行为，不据此推断角色可以穿墙。
- 其余分支优先检查左侧（左邻格通行时），否则检查右侧；同样检查第二格。
- 后退不在该构造函数输出中。另有的后退、特殊区域及占用行为不能从这里推定。

## 独立验证

`tools/verify_original_navigation.py` 使用 Unicorn 2.1.4 执行源 EXE 的方向构造及导航查询机器码，不启动 Windows 程序、不加载游戏 UI、不调用操作系统 API。

构造实际地图内存布局，保留原导航查询对边界、有效层、0x80、0x40、运行时占用槽的检查。当前样本为小镇单层地图、占用槽全零。遍历 124 个普通道路格、四种朝向，共 **496 个机器码结果**，存入 `tests/fixtures/original-town-navigation.json`。JavaScript 方向函数与所有结果逐项对比。

起点 (24,24) 朝北返回 13，即北/西/东；下一格 (24,23) 朝北返回 1，即仅北。修复了旧试作在后一处错误提供向东转弯的问题。
