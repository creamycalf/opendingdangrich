普通地产等级从 0 到 4，价值系数为 `[1,1.5,2.25,3.375,5.0625]`。
升级费为当前等级系数乘当前地价，截断为整数；出售为当前等级系数乘当前地价再除以 2，截断为整数。

租金系数为 `[0.5,0.75,1.125,1.6875,2.53125]`。先逐块计算相连且同地主的地产租金并按 float32 累加，再乘相连地块数量。例如两块 50 元、等级 0 的相连地产合计收取 `(25+25)*2=100`。不同地主、道路及不相连地块会切断连片。

价格倍率参与计算：基础租金和交易报价先将地图价格乘 float32 倍率并截断。资产估值的基础价格保留 float32，不能直接复用交易报价。

## 独立校验

`tools/verify_original_economy.py` 直接在 Unicorn 中执行原 x86：保留真实地图查询、递归遍历、链表和浮点计算，只替换内存分配/释放及调试 sprintf。没有启动 Windows 游戏界面，没有替换规则函数。

生成 `tests/fixtures/original-property-charge.json`：八图共 2,965 个租金结果、2,485 个出售报价和 1,988 个升级报价。覆盖每块普通地产的五个等级、混合地主、相连地产以及非整数价格倍率。`tests/property.test.mjs` 对独立实现逐项比较，无误差容限。

主引擎已接入这些基础公式；允许小数余额、债务、存款并使用 float32 收付款。HUD 及金额文案显示截断后的整数，账本保留小数。每个实际停靠角色按连片计算；覆盖小数欠款、提取存款、续存档及旧规则迁移。

旧 `town-flow-2` 存档保留余额、地产、队列及已确定的待付金额；仅未来交易用新公式。旧规则回放不允许悄悄按新公式执行。
