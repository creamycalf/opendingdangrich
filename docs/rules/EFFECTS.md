# 道具计时、护身符与空气枪

2026-11-03，首次接入规则版本 `town-flow-5`，后续 `town-flow-6` 保留这些状态。这里恢复的是现有两种道具的计时、空气枪基础命中和同类状态处理，不是完整 42 道具系统。

## 原程序依据

源文件仍为工作区 `wa.exe`，SHA-256 `f190b35370d3efe3024b5105a90f85abf07f5915e7b7a431d93b756de03f65f3`。

| 地址 | 已确认行为 |
| --- | --- |
| `0x48be40` | 工厂和构造函数：护身符初始持续数 5，空气枪 3。 |
| `0x438960` | 正常结束行动后设置玩家状态位 `0x10`；`0x43879b` 的追加行动分支绕过这一段。 |
| `0x43c158` | 进入角色行动阶段时设置 `0x2000`；正常结束时清除此位。 |
| `0x439fea..0x43a16f` | 若 `0x10` 存在，清除它、设置 `0x4000`，遍历角色的已附加道具调用虚表 `+0x34`；没有标志则不扣。 |
| `0x48dadf` | 剩余值小于 10 时减一；零返回失效。值大于等于 10 是不递减哨兵，不能当普通天数处理。 |
| `0x43adf3..0x43ae1f` | 附加道具时，接收者不在行动中且 `0x4000` 已设置，则持续数补一。首次行动前、尚未完成第一次计时、行动中的角色，不能一律补一。 |
| `0x43904b` | 同一类型、同一施用者的状态返回拒绝码 3；相同类型来自不同施用者可共存。本次已对 28/36 两类型执行验证。 |
| `0x49e3de..0x49e434` | 真人空气枪：施用者能力位 `0x01000000` 为必中；否则从 1000 个随机结果中，700..999 命中。未命中仍消耗行动和道具。 |
| `0x451c94` | 大雄构造路径设置 `0x11000000`，包含上述必中位；同路径使用头像起始号 27，已与原头像图像核对。 |
| `0x49e956` | 空气枪计时到期调用 `0x438cf9` 唤醒；后者清除角色 `+0x114` 睡眠字段。 |

护身符在多个仙人选择中持续生效，不因一次好运被消耗。原先只有一次保底的实现已改为可存档的持续状态。仙人事件本身仍是未恢复的临时宝箱逻辑，本次不把其金额与事件种类算作完成。

空气枪的睡眠与炸弹等旧 `skip` 分开。施用者、剩余值、是否正在睡眠分别保存。同一角色不能反复刷新自己已施加的同种状态；不同施用者保留独立计时。原到期回调会直接唤醒，即使另一个施用者的空气枪对象尚未到期；实现保留这个可见的原代码行为，而未自行把它改为“所有计时都到期才醒”。

## 验证与接入

`tools/verify_original_effect_clock.py` 执行原始代码并生成 `tests/fixtures/original-effect-clock.json`：

- 28 条多步计时轨迹，包括开始、重复开始、结束、再次开始和永久哨兵。
- 2,000 组命中判定；必中分支不调用随机函数，普通分支调用一次。
- 7 组附加状态位组合，检查是否补一。
- 4 组同类型/同源及异源冲突判断。

计时验证替换了图像刷新、列表枚举及到期对象释放；随机判定验证注入随机值及能力位。分支、计时数运算、标志位读取/清除和唤醒调用执行的是原指令。这不等于整款 PC 游戏的实机对照，也不证明当前随机数发生器与原程序同序列。

`app/src/effects.mjs` 保存独立状态逻辑；`engine.mjs` 接入回合、命中、开箱和存档；触屏和 AI 仍经同一命令边界。玩家信息显示剩余时间，过期后等待真人输入期间也立即保存，防止此时关闭应用导致再次扣时间。

旧 `town-flow-2/3/4` 存档仍可读取。已有一次性护身符和 `skip` 保持旧含义，不猜测该休息究竟来自炸弹还是旧空气枪；今后新使用的道具才采用新状态。旧规则的命令录像仍拒绝用新规则回放。

## 剩余缺口

咒语相机反射、攻击保护、其他道具之间的互斥表、机械小矮人的睡眠代行、特殊日历和完整仙人事件尚未接入。任意门仍是旧临时传送实现。上述缺口仍阻止完整版交付。
