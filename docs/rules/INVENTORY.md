# 原版开局库存与道具目录

2026-11-03，首次接入 `town-flow-7`。只恢复开局发放、完整道具身份及库存保存/出售，不代表 42 种道具效果完成。

## 机器码依据

源 EXE SHA-256：`f190b35370d3efe3024b5105a90f85abf07f5915e7b7a431d93b756de03f65f3`。

- 玩家 `+0x44` 起为 42 个 32 位道具数量。基础构造过程清零；并非最多装 12 件的背包。
- 哆啦A梦 `0x451018..0x451071`、哆啦美 `0x4531a8..0x453201`：普通新游戏标志 `0x4ca664 == 0` 时，从 `0x4c3c64` 的 25 项表不断抽取，直到收到 22 种不同道具。重复抽中会重试、继续消耗随机数。每种起始数量为一。
- 池中编号：`0,1,3,4,6,9,11,12,14,16,17,19,22,25,26,27,28,30,31,32,34,36,37,38,41`。时间布（2）不在其中；不能靠这项改动声称恢复其正常获取。
- `0x4a44b7` 真人商店购买处理先核对选中行、价格和现金。接受后 `0x4a46f1..0x4a4706` 直接增加对应数量；没有之前试作采用的 12 件总量条件。这里未推导整数溢出行为或完整商店特殊限制。
- 不能把 `0x451681` 附近“发放全部 42 种”的另一个角色构造分支当成哆啦美。其头像基号为 47，不是当前六名角色中的哆啦美 31。

`tools/verify_original_inventory.py` 执行原开局循环，仅替换随机函数的输出；表读取、去重、循环结束与库存写入均使用原机器码。58 组覆盖双角色、不同顺序、重复抽取、各池项遗漏以及非新游戏标志。另执行 252 组已接受购买的数量递增，覆盖每个道具和 0/11/12/22/99/1000 的原数量。夹具：`tests/fixtures/original-inventory.json`。

## 独立引擎接入

- `inventory.mjs` 将旧五个字符串键保持不变，其他道具使用 `original-N`，共 42 个稳定身份。原作说明由 `export_item_catalog.py` 从既有解码目录生成；无需运行时联网。
- 新局创建完成玩家后顺序抽取，将消耗后的随机状态存入同一存档。当前引擎 PRNG 仍与原 Windows RNG 不同；证明的是对同一输入抽样序列的取物算法，不是整个原游戏随机序列一致。
- 沿用字符串数组的存档表示，删除 12 件限制；原作计数和此表示在正常数量下等价。原生存储层仍有 2 MB 文本限制，这是实现资源上限，不是原作背包规则。
- `town-flow-2..6` 继续迁移。加载旧存档不会补发、重抽或消耗随机数，保留旧库存、余额、待处理操作和持续状态。
- 未实现效果的道具可保留、查看原作说明、按原店回收价格出售；不能使用或新购买。界面标明“效果待还原”。这是内部开发限制，不是原作限制。现有任意门的原作差异也在道具说明中直陈。
- 后续 `town-flow-8` 已核对月初调用时点并接入大雄/静香发放，见 [MONTHLY-GIFTS.md](MONTHLY-GIFTS.md)。完整 AI 选购、其他角色的全套库存来源、角色条件过滤仍需恢复。

验证：五项新增 Node 测试覆盖原循环对照、42 种身份读档、双角色开局与迁移、超过 12 件的买卖、未实现效果拒绝使用但可出售。浏览器和 Android 增加小屏长列表、原说明、禁用按钮及返回后不消耗回合的检查。完整内容缺口仍见 `FULL-GAME-ACCEPTANCE.md`。
