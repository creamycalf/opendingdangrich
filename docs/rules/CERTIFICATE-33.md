# PC v1.26 结算证书

原 EXE SHA256 b99f70be2a703b7f20e5d7dbf6d29f2ffca86303f4be420bf9fb334cbe792eb1。

0x454124 输出八个 DWORD，依次为角色、座位、总资产 float、普通地产等级 0 至 4 的数量。类型 2 和 3 的特殊建筑不计入五项数量。0x44fc48 的总资产包含现金、矿山存款、步行积分及按通胀和等级折算的地产原值。证据保存在 research/v126-score-fields.json 和 v126-score-assets.json。

0x46f0e8 接收这八个字段，展示证书、资产和评级，再接受名字、保存 result.dat。黄耳角色跳过后面的签名与证书写入流程。等级素材 612 至 617 经原图解码确认为 S、A、B、C、D、E。评级使用单精度总资产除以已过日数，分界为 900、600、500、400、300。

计日器 0x4cc7b0 在开局初始化为 0，每个日期推进加 1。破产胜利在日期推进后的检测中回退 1。年期届满保留已过日数，对应当前对局 g.round-1。证据为 research/v126-certificate-flow.json。原版同资产赢家采用第一个存活席位，电脑赢家进入不同的结束分支。

tools/verify_v126_certificate.py 隔离执行原程序 0x46ff0a 至 0x46ffd1，生成 60 组 tests/fixtures/pc-v126-certificate.json。包含负资产、单精度边界和零日数。首日正资产除零得到 S，0/0 的 x87 无序比较走全部降级分支得到 E。

永久黄耳记录在原蓝叮当取得 S、开局电脑数为 3 时写入。前五项由 random(100) 取得，第六项为 6−前五项总和 mod 6。角色选择处要求六项全部非零且和可被 6 整除，因此原随机取得零时会继续锁定。快捷输入 GO2HIDDENCHAR 单独开启本次会话。存储实现将每局颁奖尝试和当前六项一起写入，重复查看不会重抽。随机仅在结算局部副本运行。

RC10 接入原证书和等级图、签名和本机留存。新 v1.26 对局同资产时由首席位获胜，与 0x474525 按席位遍历且仅在资产严格增加时替换获胜者一致。较早版本创建的存档沿用当时的并列结算，保存其命令回放行为。手机证书采用本机存储格式；PC result.dat 与实体打印仍待处理。
