# 安卓存档写入与冷启动

2026-11-03 的实际 Android 强制停止测试发现：在复原光线改变建筑后，WebView 的 `localStorage` 已返回新状态，但立即杀进程再打开，仍可能读到使用道具前的磁盘值。浏览器内刷新测试不能发现这个问题。

新增本地 Capacitor 插件 `GameSavePlugin`，使用应用私有 `SharedPreferences`；在 Capacitor 的后台处理线程调用同步 `commit()`，成功后才向 JavaScript 确认。没有网络、文件共享或新增系统权限。

`app/src/save-store.mjs` 串行提交快照，避免较早存档在较晚存档之后完成。安卓首次启动会把既有 `dingdang.touch.v2` WebView 存档迁入原生存储。迁移后原生存储为准，WebView 存储保留为界面缓存；即使原生存档已清空，也不让旧缓存复活。浏览器运行继续使用原存储键。

回合循环在每次持久化后才继续推进、开放下一次操作。保存按钮及“保存并返回主菜单”在收到磁盘写入确认后才显示成功/退出；写入失败显示错误并暂停推进，允许重试。异步保存等待期间若已离开当前对局，不再推进旧回合。

重载测试也发现了首次原生读取回调丢失：本地 Capacitor 7 的 `MessageHandler` 先把调用交给插件线程，再更新 WebMessage 的回复代理。插件的快速读取有机会向上一页面的代理回复。插件现在将完成/错误回复投递到主线程队列，确保当前 WebMessage 监听回调结束后再回复；磁盘操作仍在后台处理线程，不修改 Capacitor 依赖，也不切换到旧版 JavaScript bridge。

单元验证覆盖迁移、旧缓存覆盖防护、清空标记、提交顺序、等待确认、失败重试、浏览器存储空间不足。安卓测试在道具使用后等待正常可操作状态，核对原生快照，立即 `am force-stop`，冷启动后与使用后的状态逐字段比较，不用额外延时掩盖丢档。

`town-flow-8` 新增月初发放月份标记，随库存提交同一快照。安卓实际验证大雄领取并使用空气枪、静香随后领取两件道具，立即强制停止后冷启动不重复领取；旧 `town-flow-2..7` 存档保留已有库存并跳过当前月追补，下月恢复领取。

这是已确认写入后的进程强制停止恢复保障，尚不能代替真实设备、系统断电和磁盘损坏测试。完整游戏内容仍未恢复，见 FULL-GAME-ACCEPTANCE.md。
